**Rev B (2026-08-02):** Replaces the Rev 1 session descriptor (`np_pbm1064_session_desc_t` v4: 8-bit `smart_module_mask` + fixed `zone[5]` array) with **session descriptor v5** (§1): a small list of (128-bit socket mask, preset) groups, reusing NP Hub Protocol v2's `NP_PROTO_TARGET_SOCKET_MASK` bitmap representation per the binding requirement in NP-HW-HUB-001 Rev 3 §10. v4 could name at most 5–8 of the ~30–128 sockets NP-HEX-ZM-001's hex lattice actually has; v5 can name any of them, without reintroducing the duplicate-socket / double-dose defect a socket-ID list would carry (NP-HEX-ZM-001 §4b). §6.2's T2 combined descriptor is updated to match (inlines the header + groups rather than embedding a v4 sub-descriptor by value). UHDR/SHDR records (§4, §6.7) move from fixed 5-zone arrays to per-active-socket entries with an explicit `socket_id` per entry. Calibration coefficients are **not** re-indexed by socket in this revision — see NP-FW-PBM1064-001 Rev 3 §6.2/§6.6 and NP-HW-HUB-001 Rev 3 §9.5 (OI-HUB-C06: must be keyed to module UID, not socket, because modules are swappable).

Implemented and host-tested in `firmware/pbm_1064nm/` (`np_pbm1064_session_desc_wire_len/_signed_len/_serialize/_parse/_expand`, `firmware/pbm_1064nm/tests/np_pbm1064_session_desc_tests.c`, 55/55 checks; full firmware host suite 21/21 unchanged).

## 1. Session Descriptor v5

The app generates a session descriptor, signs it with the device-resident Ed25519 signing key, and delivers it over USB-C or BLE to the hub. The hub firmware verifies the signature before any I2C writes (signature verification itself remains a stub pending OI-PBM-SIG — unchanged from v4 — but the byte span it must cover is now correctly computed for the variable-length wire format below).

### 1.1 Wire layout

```c
/*
 * np_pbm1064_session_desc_t — NP-SES-1064-001 Rev 2 (v5)
 * Wire format is VARIABLE LENGTH: header (8B) + hdr.group_count groups
 * (22B each) + signature (64B). The in-RAM struct below has a fixed
 * MAX_PRESET_GROUPS capacity so firmware can hold a parsed descriptor
 * without dynamic allocation, but only the first hdr.group_count groups
 * are ever transmitted or signed — see §1.2.
 */

#define NP_SES1064_VERSION              0x05
#define NP_PBM1064_SOCKET_MASK_BYTES    16   /* 128 bits, LSB-first, 0-based;
                                                 == NP_HUB_SOCKET_MASK_BYTES */
#define NP_PBM1064_SESSION_MAX_PRESET_GROUPS  4

typedef struct {
    uint8_t  cur_a;             /* 660nm current setpoint (0–255 → 0–180 mA) */
    uint8_t  cur_b;             /* 808nm current setpoint */
    uint8_t  cur_c;             /* 1064nm current setpoint */
    uint8_t  freq_hz;           /* initial PWM frequency (2/6/10/20/40/0=CW) */
    uint8_t  duty;              /* initial duty cycle (0–50; ≤0x32 enforced) */
    uint8_t  channel_mask;      /* bit[0]=CH_A, bit[1]=CH_B, bit[2]=CH_C */
} np_pbm1064_preset_t;           /* 6 bytes — unchanged per-socket field semantics from v4 */

typedef struct {
    uint8_t              mask[NP_PBM1064_SOCKET_MASK_BYTES]; /* socket S is byte S/8, bit S%8 */
    np_pbm1064_preset_t  preset;                              /* applied to every socket in mask */
} np_pbm1064_preset_group_t;      /* 22 bytes */

typedef struct {
    uint8_t  version;              /* NP_SES1064_VERSION = 0x05 */
    uint8_t  eeg_adaptive_mode;    /* 0=uniform, 1=gradient (OI-SES-02) */
    uint8_t  group_count;          /* 0..NP_PBM1064_SESSION_MAX_PRESET_GROUPS entries follow on the wire */
    uint8_t  reserved0;
    uint16_t duration_s;           /* total session duration (60–3600) */
    uint16_t reserved1;
} np_pbm1064_session_desc_hdr_t;   /* 8 bytes — same size as v4's header */

typedef struct {
    np_pbm1064_session_desc_hdr_t hdr;
    np_pbm1064_preset_group_t     groups[NP_PBM1064_SESSION_MAX_PRESET_GROUPS]; /* capacity, NOT wire length */
    uint8_t  signature[64];        /* Ed25519 — see §1.2 for the exact covered span */
} np_pbm1064_session_desc_t;
```

A session descriptor with `group_count = 1` and one group naming a single socket has a wire size of `8 + 22 + 64 = 94` bytes; the maximum, at `group_count = NP_PBM1064_SESSION_MAX_PRESET_GROUPS = 4`, is `8 + 4·22 + 64 = 160` bytes.

### 1.2 Why a list of (mask, preset) groups, not a per-socket ID list

Two requirements shaped this, both from NP-HW-HUB-001 Rev 3 §10 and NP-HEX-ZM-001 §4b:

- **Reuse the existing socket-bitmap representation.** NP Hub Protocol v2 already defines a 16-byte, 128-bit, LSB-first, 0-based socket bitmap (`NP_PROTO_TARGET_SOCKET_MASK`, `firmware/hub_control/include/np_hub_config.h`) sized to `NP_HEXMAP_MAX_SOCKETS`. A per-socket ID list is rejected: under inclusive midline zone membership, a socket can legitimately appear in more than one authored zone, and a list carries that duplicate straight to the driver — a duplicate means **double J/cm² on the same module**. A bitmap cannot express the duplicate, so the dedup guarantee stops depending on every producer remembering it. `NP_PBM1064_SOCKET_MASK_BYTES` is kept numerically equal to hub_control's `NP_HUB_SOCKET_MASK_BYTES` (both 128 bits) without a header `#include` dependency, since `firmware/hub_control` links `firmware/pbm_1064nm` and not the reverse; host tests assert the values match.
- **Per-socket field independence must carry over.** v4's `zone[5]` array let every zone carry its own current/frequency/duty independently — the mechanism behind split-zone protocols like "Gamma+theta coupled" (§2, preset `0x05`). A single mask + single preset cannot express that. v5 uses a **list** of (mask, preset) groups instead: each group is one socket bitmap plus the one preset applied to every socket in it. A session realistically needs at most a couple of distinct simultaneous presets, so `NP_PBM1064_SESSION_MAX_PRESET_GROUPS = 4` is a generous bound, not a scaling limit — the bitmap inside each group already spans the full 128-socket domain.

At session start, firmware expands the groups into a flat, ascending, deduplicated active-socket list (`np_pbm1064_session_desc_expand()`): if a socket's bit is set in more than one group, the **first group (lowest index, i.e. earliest in the signed byte stream) wins**. The expansion is bounded by `NP_PBM1064_SESSION_MAX_ACTIVE_SOCKETS` (32) — a session whose combined groups address more distinct sockets than that is **rejected before any hardware is touched**, not silently truncated to a partial session.

### 1.3 Signature coverage — the security-relevant part

**The Ed25519 signature covers exactly the transmitted bytes, and that byte count is a function of `group_count`, not a fixed `sizeof()`.**

```
signed_len(group_count) = wire_len(group_count) − 64
wire_len(group_count)   = sizeof(hdr) + group_count · sizeof(group) + 64
```

This must be computed this way rather than as `sizeof(np_pbm1064_session_desc_t) − 64` (the v4 rule, restated naively): the in-RAM struct's `groups[]` array is sized to the *capacity* (`NP_PBM1064_SESSION_MAX_PRESET_GROUPS`), and only `group_count` of those slots are ever populated from — or written to — the wire. Signing (or verifying against) the full capacity would mean the signed span extends over group slots the sender never filled in, which is exactly the kind of gap that lets bytes from one message's padding be spliced into another's signed range. `np_pbm1064_session_desc_wire_len()` / `_signed_len()` / `_serialize()` / `_parse()` (`firmware/pbm_1064nm/include/np_pbm1064_session.h`) are the canonical implementation of this rule; `_parse()` additionally rejects a blob whose length doesn't exactly match `wire_len(group_count)` for the `group_count` it declares — a short or padded blob is refused outright rather than truncated or zero-extended, so the signed span a verifier computes can never diverge from what the parser actually acts on.

Signature verification itself remains a stub (`np_pbm1064_session_start()`: "Stub: always accepts — signature check is OI-PBM-SIG pending bootloader HAL") — unchanged from v4. What v5 fixes is that the span a real verifier would need to check is now computable at all for a variable-length message; v4's fixed-size struct made this trivial but wrong (it could never address more than 5 sockets).

## 2. Session Presets (Named Protocols)

| Preset ID | Name | CH_A (660nm) | CH_B (808nm) | CH_C (1064nm) | Freq | Duty | Duration |
|-----------|------|-------------|-------------|--------------|------|------|----------|
| 0x01 | Gamma clarity | 180 mA | 180 mA | 150 mA | 40 Hz | 25% | 20 min |
| 0x02 | Alpha calm | 150 mA | 150 mA | 120 mA | 10 Hz | 20% | 20 min |
| 0x03 | Theta memory | 150 mA | 150 mA | 120 mA | 6 Hz | 20% | 20 min |
| 0x04 | Sleep deep | 120 mA | 120 mA | 100 mA | 2 Hz | 15% | 30 min |
| 0x05 | Gamma+theta | 180 mA | 180 mA | 150 mA | 40/6 Hz split | 25% | 20 min |
| 0x06 | Focus prime | 160 mA | 160 mA | 130 mA | 20 Hz | 22% | 20 min |
| 0x07 | Vascular baseline | 100 mA | 100 mA | 80 mA | CW | 100% CW | 10 min |
| 0xFF | Custom | app-defined | app-defined | app-defined | app-defined | ≤25% | app-defined |

All preset duty values are ≤ 25% (DUTY_MAX_REG enforcement). Preset 0x07 uses CW mode (PWM_FREQ = 0x00, DUTY register unused; CH_ENABLE drives constant current).

Under v5, preset `0x05` ("Gamma+theta") is realised as **two preset groups** in the session descriptor — one group's mask covering the 40 Hz sockets, the other's covering the 6 Hz sockets — rather than a single row with a compound "40/6 Hz split" frequency field. The app compiles the named preset into the appropriate group split at protocol-authoring time; the wire format itself has no notion of a "split preset," only independent groups.

## 3. EEG-Adaptive Frequency Mapping

The EEG processing layer delivers `eeg_dominant_freq_hz` as a float once per second. Session firmware maps it to the nearest supported driver PWM code:

| EEG dominant band | Freq (Hz) | Driver code |
|-------------------|-----------|-------------|
| Delta (0.5–4) | 2.0 | 0x01 |
| Theta (4–8) | 6.0 | 0x06 |
| Alpha (8–12) | 10.0 | 0x0A |
| Beta (12–30) | 20.0 | 0x14 |
| Gamma (>30) | 40.0 | 0x28 |

Hysteresis: frequency code only changes if `eeg_dominant_freq_hz` has been in the new band for ≥ 3 consecutive 1 s ticks (prevents rapid switching at band boundaries). Uniform-mode EEG-adaptive updates apply the new code to every active socket in the session's expanded socket list.

## 4. Session Data Flow (UHDR / SHDR)

```
Session start
│
├─ UHDR: session_start_unix, protocol_params, active_socket_list      → UHDR partition
│
├─ Every 100 ms (dose tick)
│   ├─ PD1_counts[socket][wl], PD2_counts[socket][wl]                → UHDR (ring buffer)
│   └─ dose_J_cm2[socket][wl] (cumulative)                           → UHDR (updated)
│
├─ Every 1 Hz (NTC tick)
│   └─ NTC_temp_C[socket]                                             → UHDR
│
├─ Every 5 s (I2C status poll)
│   └─ fault_latch register value                                     → SHDR (fault log if non-zero)
│
├─ EEG adaptive event (on freq change)
│   └─ {timestamp_relative_s, old_freq, new_freq}                    → UHDR
│
└─ Session end
    ├─ np_pbm1064_session_record_t (per-socket dose entries)          → UHDR (EDF+ annotation)
    └─ np_pbm1064_shdr_summary_t (per-socket device-health entries)   → SHDR
```

`np_pbm1064_session_record_t` and `np_pbm1064_shdr_summary_t` each carry an `active_socket_count` plus an array of per-socket entries (each entry carries its own `socket_id`) sized to `NP_PBM1064_SESSION_MAX_ACTIVE_SOCKETS` — array position no longer implies socket identity the way v4's fixed `[zone]` indexing did, because a session's active sockets are an arbitrary subset of the 128-socket domain, not necessarily the lowest-numbered ones.

## 5. Ramp Profile

30 s linear ramp on all active sockets. Ramp tick rate: 10 Hz (same as dose tick).

```
duty_step = target_duty / (30 × 10)   // per 100 ms tick
ramp_duty = duty_step × tick_count
```

Duty is written to every socket in the session's expanded active-socket list simultaneously each tick (I2C write burst per socket — tunnelled through the owning cluster controller under NP-HW-HUB-001 Rev 3's I2C fan-out, not a direct per-socket bus). On ramp abort (fault), all channels set to duty=0 and CH_ENABLE=0x00 within 100 ms.

## 6. T2 Combined Session (1064nm Cortical + 1170nm Subcortical)

**Document:** NP-SES-1064-001 §6  
**Firmware:** `np_pbm1064_t2_combined` (`firmware/pbm_1064nm/`)  
**Status:** Issue #55 — software PASS; hardware FAI pending T2 prototype

### 6.1 Three-Tier Penetration Stack

The T2 combined session delivers coordinated multi-depth PBM via three laser subsystems operating simultaneously under a single session orchestrator:

| Tier | Wavelength | Depth | Subsystem | Targeting |
|------|-----------|-------|-----------|-----------|
| Surface | 660 nm (CH_A) | 0–5 mm | Smart zone module | Full scalp coverage |
| Cortical | 1064 nm (CH_C) | ~20–30 mm | Smart zone module | Protocol-defined socket set, not capped at a fixed count (NP-HEX-ZM-001 §4a SMART-1) |
| Subcortical | 1170 nm | ~35–40 mm | T2 TEC-stabilised laser | sLORETA-guided (T2 depression protocol) |

This architecture replicates the depth-tier rationale from the penetration physics literature (Bashkatov 2005, Strangman 2002 — NP-BIB-1064-001 Rev 1 entries 12.3a–12.3c).

### 6.2 Combined Session Descriptor

```c
/*
 * np_t2_combined_desc_t — NP-SES-1064-001 §6.2 (v5)
 * Ed25519 signature covers all fields at bytes 0 .. (signed_len - 1);
 * see np_pbm1064_t2_combined_desc_signed_len() — signed_len is a function
 * of pbm1064_hdr.group_count, same rationale as §1.3.
 * Hub firmware verifies before any laser enable.
 */
typedef struct {
    uint8_t  version;              /* NP_T2_COMBINED_VERSION = 0x01                */
    uint8_t  t2_combined_enable;   /* 1 = activate 1170nm laser                    */
    uint8_t  sloreta_enable;       /* 1 = read sLORETA MNI target at session start  */
    uint8_t  reserved;
    np_pbm1064_session_desc_hdr_t pbm1064_hdr;      /* inlined, not embedded by value */
    np_pbm1064_preset_group_t     pbm1064_groups[NP_PBM1064_SESSION_MAX_PRESET_GROUPS];
    np_t2_1170_preset_t           laser1170;        /* { duty_pct, freq_hz, duration_s } */
    uint8_t  signature[64];        /* Ed25519                                      */
} np_t2_combined_desc_t;
```

The 1064nm fields are **inlined** (header + groups) rather than embedding a full `np_pbm1064_session_desc_t` by value, as v4 did. Embedding the v4 sub-descriptor by value carried its own unused `signature[64]` field along for the ride, which read as though the inner descriptor could be independently verified when only the outer signature ever was checked. `np_pbm1064_t2_start_combined()` builds a standalone `np_pbm1064_session_desc_t` from `pbm1064_hdr` + `pbm1064_groups` (with a zeroed signature field, since only the combined descriptor's own signature is ever verified) before handing it to `np_pbm1064_session_start()`.

### 6.3 Parallel Ramp Coordination

Both the 1064nm smart zone session and the 1170nm laser ramp **in parallel** from a single combined safety MCU enable:

```
t = 0                            t = 30s               t = session_end - 30s
│                                │                      │
├─ 1064nm ramp 0→target duty ───►│ full duty ──────────►│ ramp down 30s
├─ 1170nm ramp 0→laser_duty ────►│ full power ─────────►│ ramp down 30s
```

- Safety MCU issues a single combined enable at `t = 0` (SPI write from main processor).
- Hub firmware drives the 1170nm ramp duty via `np_pbm1064_hal_t2_1170_set_duty()` at 100 ms tick rate, parallel with the 1064nm ramp in `np_pbm1064_session_tick()`.
- Ramp abort on any fault immediately disables both subsystems within 100 ms.

### 6.4 Thermal Throttle Priority Cascade

When aggregate thermal load triggers throttle, the priority cascade is applied one step per call to `np_pbm1064_t2_apply_thermal_throttle()`:

| Step | Subsystem | Rationale |
|------|-----------|-----------|
| 1 | 1170nm TEC laser | Deepest penetration; highest per-watt subcortical heat deposition |
| 2 | 1064nm CH_C (smart zone) | Cortical depth; second-highest thermal contribution |
| 3 | 808nm CH_B (smart zone) | Mid-surface; lower thermal contribution |
| 4 | 660nm CH_A (smart zone) | Surface only; last resort |

Steps 2–4 iterate the session's expanded active-socket list, not a fixed zone range. TEC temperature is polled every 1 s via `np_pbm1064_hal_t2_1170_get_temp()`. Threshold `NP_T2_1170_TEC_FAULT_C` (45 °C) triggers step-1 throttle; `NP_T2_1170_TEC_CUTOFF_C` (50 °C) triggers immediate abort.

### 6.5 sLORETA Depression Protocol Coordination (T2, OI-SES-T2-01)

For the T2 depression protocol, the sLORETA engine (NP-FW-HD-001 Rev 1) provides the MNI cortical target at session start. The 1170nm laser is positioned to irradiate subcortical regions below the identified cortical source.

**Workflow (when `sloreta_enable = 1`):**
1. App runs T2 21-ch resting-state qEEG session.
2. sLORETA computes source power map; identifies peak MNI target (e.g., DLPFC hypoactivity).
3. App sets `sloreta_enable = 1` in combined descriptor.
4. At `np_pbm1064_t2_start_combined()`, firmware reads MNI target via `np_pbm1064_hal_t2_sloreta_get_target()`.
5. MNI coordinate logged to UHDR combined record. Clinician app displays depth-tier alignment illustration.
6. **Hardware coordination (pending T2 prototype):** Laser arm positioning from sLORETA MNI → physical placement is a procedural step; firmware records the target but does not drive robotic positioning in this revision.

**Stub behaviour (current):** `np_pbm1064_hal_t2_sloreta_get_target()` returns DLPFC_L stub coordinates (MNI x=-40, y=40, z=30) with `valid = true` so that FAI-T2-01 and FAI-T2-03 exercise the logging path.

### 6.6 Session State Machine

```
T2_IDLE → T2_PREFLIGHT → T2_RAMP_UP → T2_ACTIVE → T2_RAMP_DOWN → T2_COMPLETE
                                            ↕
                                        T2_FAULT
```

`T2_PREFLIGHT`: 1064nm preflight (I2C probe, NTC check) + sLORETA target read + 1170nm enable.  
`T2_RAMP_UP`: parallel 30 s ramp for both subsystems.  
`T2_ACTIVE`: full dose; TEC poll at 1 Hz; 1064nm dose tick at 10 Hz.  
`T2_RAMP_DOWN`: parallel ramp-down; 1064nm drives ramp, 1170nm mirrors proportionally.  
`T2_COMPLETE`: final 1170nm dose read; both subsystems disabled; UHDR + SHDR written.  
`T2_FAULT`: all channels disabled immediately; both records written with fault reason.

**SHDR — np_t2_combined_shdr_summary_t (device-owned, no user biology)**

| Field | Type | Notes |

Both records grew from v4's fixed 5-entry arrays to `NP_PBM1064_SESSION_MAX_ACTIVE_SOCKETS` (32) entries — a consequence of addressing breadth, not of any new per-sample or user-identifying field; the SHDR side still carries no raw PD counts, no timestamps, and no user biology, only a per-socket ratio/pass-fail summary.

## 7. Safety Limits Summary

| Parameter | Limit | Enforcement |
|-----------|-------|-------------|
| Duty cycle max | 25% (0x32) | Firmware ceiling, unconditional |
| 660nm dose/session | 60 J/cm² | Dose tick; channel disable on limit |
| 808nm dose/session | 60 J/cm² | Dose tick; channel disable on limit |
| 1064nm dose/session | 36 J/cm² | Dose tick; channel disable on limit (OI-SES-01) |
| **1170nm dose/session** | **60 J/cm²** | **T2 combined dose tick; laser disable on limit** |
| Aggregate irradiance | 600 mW/cm² | Throttle cascade; pending OI-PBM-05 |
| NTC junction temp | 62 °C | Hardware current throttle + firmware gate |
| IEC 60601 surface temp | 42 °C | Safety MCU GPIO interlock |
| **TEC fault temp** | **45 °C** | **1170nm step-1 throttle** |
| **TEC cutoff temp** | **50 °C** | **Immediate 1170nm disable + session abort** |
| Safety MCU heartbeat | 200 ms | Main processor SPI; 1.5 s watchdog → all-disable |
