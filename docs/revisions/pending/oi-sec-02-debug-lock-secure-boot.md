text: - [ ] **`OI-SEC-02` (raised 2026-11-23, from `OI-PRIV-39` (NP-PRIV-ANALYSIS-004) part (2) and `NP-PRIV-ANALYSIS-004` "What could not be reviewed"; `CLAUDE.md` §4.1, §4.2, §5.1, §23; `firmware/bootloader/src/np_main.c:73`, `:103`; `NP-FW-NVRAM-001` row 8; `NP-REG-UPG-001` §7.7 item 2 and `OI-UPG-08` (iv); `FMEA-M10-05`; GitHub #967) — production debug-port lock and secure boot are specified for neither processor.** Searched 2026-11-23 across `docs/`, `firmware/bootloader/` and `firmware/safety_mcu/` for JTAG, SWD, SJC, HAB, RDP, option bytes, secure boot and readout protection. **Main processor (i.MX RT1062): nothing.** No document specifies that the debug port (SJC, JTAG/SWD) is disabled or locked in production, or that the boot fuses are put in HAB closed configuration. The bootloader's image header sets `csf = 0`, which means HAB is disabled (`firmware/bootloader/src/np_main.c:103`). `NP-FW-NVRAM-001` row 8 names "HAB keys" as the root of trust and nothing more. The bootloader verifies each application bank's Ed25519 signature, but no ROM stage authenticates the bootloader itself, so a party with the debug port or the serial downloader can replace it and run anything. **Safety MCU (STM32G071): planned, not specified.** RDP is required by `OI-UPG-08` (iv) for the tier-identity OTP window (`REQ-UPG-02`, `FMEA-M10-05`), but neither Level 1 nor Level 2 is chosen and nothing applies it (`docs/human-input/oi-upg-08-factory-step-scoping.md` item 4; `docs/human-input/oi-priv-25-safety-mcu-cutoff-log-erasure.md` §2.4). This item does not take that decision from `OI-UPG-08`; it records that the same lock is also what protects the per-user cutoff log (`OI-PRIV-25`). **Why it matters:** with the debug port open, anyone holding a unit can read hub RAM while a session runs (the protocol, the UHDR records and the biosignals `OI-PRIV-39` zeroes only once they are no longer needed, and the UKMD while UHDR is mounted), read the safety MCU's flash, and write firmware that bypasses the safety MCU's checks or the hub's refusals (`CLAUDE.md` §4.2). Without secure boot, the signed-protocol and signed-image chain (`CLAUDE.md` §4.2, §23) rests on a bootloader nothing authenticates. **To decide (Firmware, Manufacturing; Safety for anything that touches the safety MCU's image; Service for what a returned unit's failure analysis loses):** (a) the i.MX RT1062 production lock: SJC mode (disabled, or secure JTAG with a response key and who holds it) and when in the line the fuse is burnt; (b) HAB: closed configuration, the signing keys (SRK table, who generates and holds them, revocation), and how the bootloader is signed in the build; (c) whether flash or image encryption (BEE or OTFAD) is wanted, or ruled out with a reason; (d) the safety MCU RDP level, under `OI-UPG-08` (iv), cross-referenced here; (e) how a locked unit is debugged on return (a Level 1 regression erases flash; Level 2 is permanent) and what that costs service; (f) the production verification: a final-acceptance test that each lock is set on every unit. Every choice of level or mode is an `unjustified-choices` row until cited (`CLAUDE.md` §19). **Closes when:** (a), (b) and (d) are specified in a controlled document with an owner, (c) and (e) are decided, and (f) is in the final-acceptance procedure. `OI-SEC-01` is cited by `docs/np_priv_audit_001.md` for GATT access control but was never filed; this item does not reuse it.
