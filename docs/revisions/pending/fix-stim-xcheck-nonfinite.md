## DHF
author: NeurOne Firmware Engineering
text: **{NP-SIM-FW-001 from → to}, {NP-FW-HUB-001 from → to}: OI-SIMFW-31 opened and closed. The stimulation cross-check's non-finite test no longer depends on the compiler.** `np_stim_xcheck_observe` counted a non-finite delivered reading as an excess with `!isfinite(delivered)` ahead of the magnitude comparison. The hub is built with `-ffast-math`, which folds `isfinite()` away (arm-none-eabi-gcc 13.2.1 emits no test for it), so the NaN case rested on the condition code chosen for the magnitude comparison. GCC 13.2.1 chose one that flags NaN, so the shipped build was correct by accident; clang for Cortex-M7 chose one that does not (shown under qemu-system-arm, mps2-an500). The test is now on the float's exponent bits, as in OI-SIMFW-17. Class B only (`np_stim_xcheck.c`); no bound, tolerance or timing changed; no Class C file touched. New host test `np_stim_xcheck_nonfinite_tests` (REQ-FWHUB-41), built with the device's `-ffast-math` flags. The host test passes on x86 with the unfixed driver, so it pins behaviour and does not by itself reproduce the fault. Not changed: the same exponent test now exists in `np_mod_vns.c` and `np_stim_xcheck.c`; sharing it in one header is a follow-up. The other `-ffast-math` targets were searched for `isfinite`, `isnan` and `isinf` and have none; NaN-sensitive comparisons there were not audited.
