The hub also passes the carrier, not the rate, to `np_mod_audio_hal_set_isochronic` (observed, not investigated). **Decision owed (the principal):** allow an isochronic rate of 0 (and say what it means) or refuse it (the validator and the compiler conform to the reference). text: **2026-11-22 — The Compose modality editor's number fields mark a blank field; the three smaller items left by the 2026-11-15 sweep.** The items left open when the Compose sweep closed (#938), taken one by one. **A blank number field no longer sits beside an unchanged stored value (fixed).** The modality editor's `NumField` and `IntField` committed a value only when the text parsed and otherwise did nothing, so a cleared field (or a lone point) showed blank while the old value stayed stored and was the one saved. A field now holds a number or says it does not. **An edit that could not be the start of a number is refused and the field keeps its text** (a second point, digits too many to be finite or to fit an Int; `numberText`, `wholeNumberText`), **blank and a lone point are kept and the field is marked unread** (`isError`, with the existing `VALIDATE_MSG_GENERAL_REQUIRED_PARAMETER`, "{0} is required and was not given a number…", naming the field), and **Save is disabled while any field of the open editor is unread** (each field reports into `LocalUnreadFields`). A field that leaves the screen (its card is collapsed or its modality removed) stops reporting and, when reopened, shows the stored value again, so the collapse abandons an unread edit and nothing unread is saved. No new locale key. **Consequence:** a blank field in any modality card blocks Save for the whole editor until it is filled or the card is closed. **The rounded-down start offset does not occur (no change; an earlier statement corrected).** The #938 entry said a layer start offset that is not a whole number of minutes "still shows its minutes rounded down". On the screen as built that cannot happen: `ProtocolComposerScreen` takes no existing protocol, its layers start empty and are added with the default offset of 0, and only whole minutes can be typed. It could appear only if the composer later loads a composite authored in seconds (the web composer's unit). Nothing was built for a case the screen cannot reach, and a seconds field was rejected because it would orphan `PROTOCOL_COMPOSER_START_MIN` (the locale gate refuses an unreferenced key). **The 0 Hz beat (investigated; a finding, with a decision owed).** The hub passes a stored beat of 0 straight to the audio HAL, whose real implementation does not exist, so what it sounds like is unspecified. The `.npps` reference says the beat and the isochronic rate are "Above 0", yet the parser, the validator and the compiler all accept 0 (checked on the Rust core: no issue, and a 0 mHz beat in the descriptor), and the hub's own EEG retune path refuses 0 as "a frequency that cannot be a beat". Recorded as `OI-NPPS-AUDIO-01`: refuse 0 (recommended) or change the reference. Not decided here, because it changes the shared core and a documented bound. **The unsourced figures (`UC-191`) are not touched.** A source for each is the principal's to name; none is invented here. **Not run here:** the Kotlin compile and the new desktop test (`ModalityEditorNumberTextTest`), so CI is their first run.
