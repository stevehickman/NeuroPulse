text: - [ ] **`OI-PRIV-65` (raised 2026-11-21, `NP-PRIV-ANALYSIS-007` Findings M12, L21; `UC-087`; `common/core/.../common/PassphraseGatedSecretKeyStore.kt`, `common/core/.../data/BundleKey.kt`) — the human secrets the apps keep.** (1) **M12, reported.** The passphrase wrap record (Argon2id parameters and the wrapped data key) is written to the plain host store, so a copied preferences file can be attacked offline, protected by Argon2id and a 12-character minimum (`UC-087`, provisional) with no strength check. `openGated` already requires a platform keystore key that could wrap the record as well. (2) **L21, checked.** With the passphrase method, the automatic backup keeps the person's passphrase itself as hex (`toStoredText`) under `np.backup.auto-secret`; it is the person's documented choice, but a derived key, or a random backup key wrapped under it, would serve the same purpose without storing a secret people reuse. Related: `OI-PRIV-61`, the same secret kept in the clear on an unsealed run. **Closes when:** the wrap record is also wrapped under the keystore key or the principal accepts the offline exposure, and the automatic backup keeps a derived key or the stored passphrase is ruled acceptable. **2026-11-22: (1) fixed, (2) open, awaiting a ruling.** (1) **Fixed by new `REQ-PRES-10` (`NP-APP-PRESENCE-001`).** `PassphraseGatedSecretKeyStore` now takes the host's keystore (the key the device tier is sealed under) and seals the whole record under it with the core's `sealValue` (prefix `np-ppwrap:1:`, associated data `np.presence.passphrase-wrap#device`), so the record is still read before anyone is present, stays outside the UHDR tier and keeps the host-plain key `OI-PRIV-62` requires (the store seals it itself; neither tier's `np-enc:1:` reads it). With no keystore, or one that cannot be asked, nothing is set up or opened, and a record that does not open under this device's key is `FAILED`, never `WRONG`, so a copy cannot test a guess. A record in the clear is refused, not read: no host has offered the gate (`OFFER_PRESENCE_GATE` is false everywhere), so none exists, as the 2026-11-19 rulings held for the archive and the bundle. The desktop host passes `{ secretKeyStore }`. Tests: `PassphraseGatedSecretKeyStoreTests` (`REQ-PRES-10#a`: the record shows no Argon2 field, a copy with another or no keystore opens nothing with the right passphrase, no keystore sets nothing up, a keystore that cannot be asked has no key made over it; `#b`: a record in the clear is refused and not rewritten), and the existing gate tests now run with the device key (`NoKeyInARequestTests`, `PresenceGateTest`). **What it does not reach:** a copy that includes the keystore (on the desktop, the same login's credential store); there Argon2id and `UC-087` are still the whole defence. (2) **Open: needs a decision, not a detail** (`docs/human-input/oi-priv-65-automatic-backup-secret.md`). A stored derived key fits one salt while the backup flow draws a new salt per bundle, and keeping it across runs needs a sealed export of a core-kept key, which `SWR-MG-32` (b) forbids (the principal, 2026-11-19); a random backup key wrapped in the header is a bundle format change. Nothing in `OI-PRIV-61`'s fix (keep the value out of an unsealed run) is duplicated here.
