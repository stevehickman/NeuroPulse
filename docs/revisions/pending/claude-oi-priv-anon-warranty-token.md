text: - [ ] **`OI-PRIV-74` (raised 2026-11-23, noticed while fixing `OI-PRIV-26` (NP-PRIV-ANALYSIS-004), PR #979; `CLAUDE.md` §5.3; `docs/reference/data-architecture-detail.md` §5.3 step 4; `NP-FW-ANON-001` §7.2) — the firmware anonymisation spec still puts a device identifier in every research extract.** `NP-FW-ANON-001` §7.2 wraps each extract in an envelope that carries `device_warranty_token` (the opaque token that keys SHDR, `CLAUDE.md` §5.1) and a `device_signature` made with a per-device Ed25519 key. Both are the same in every study, so any two extracts from one device can be joined to each other, and the token also joins them to that device's SHDR record and, through the warranty database, to its registrant. That contradicts the principal's ruling on `OI-PRIV-67` (2026-11-20): an extract is stored keyed to **study ID only**, and "no device identifier, token or serial travels with an extract" (`data-architecture-detail.md` §5.3 step 4). `OI-PRIV-67` updated §5.3 and `NP-IRB-001`, not `NP-FW-ANON-001`, which is still Rev 2 with the original envelope. **Nothing is built that sends it:** no code builds the envelope (`firmware/anon/` has no envelope writer, and no app extractor exists, `OI-CONSENT-07`), so this is a spec defect to fix before anyone builds from §7.2. **No ruling is owed to remove the token:** `OI-PRIV-67` already decided it. **A design choice may be owed for the signature:** the envelope still needs a way to show an extract is genuine without a key that names the device. A per-device key links extracts across studies; a per-study key derived from a UHDR-held secret (as `OI-PRIV-70` does for a tracking identifier) still links one person's releases within a study, which a study that declared no tracking must not allow. If no mechanism avoids both, which to give up is the principal's decision. **Closes when:** `NP-FW-ANON-001` §7.2 carries no device identifier, token, serial or per-device key; the authenticity mechanism is chosen and written there, with the linkage it allows stated against `OI-PRIV-70`'s tracking rule; and the envelope is checked against §5.3 step 4. **Decision brief (DRAFT, not sent):** `docs/human-input/oi-priv-74-extract-authenticity.md` asks Q1 (must the store refuse a forged extract?) and Q2 (anonymous tokens, group signatures, or reversing `OI-PRIV-67`); it recommends Q1 yes, Q2 anonymous tokens (Privacy Pass).
