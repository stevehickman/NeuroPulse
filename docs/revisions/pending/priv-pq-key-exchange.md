text: - [ ] **`OI-PRIV-73` (raised 2026-11-23, follow-up to `OI-PRIV-35` (NP-PRIV-ANALYSIS-004); checked; `CLAUDE.md` §5.1, §22, §23; `common/npps-core/src/link.rs`, `ohttp.rs`, `bundle_key.rs`, `archive.rs`; `firmware/bootloader/src/np_app_image.c`, `np_dfu.c`; `docs/human-input/oi-simfw-71-secure-channel-design.md` §4, §14) — no path uses post-quantum key exchange, and the helmet channel designed to carry UHDR agrees every key over elliptic curves.** Backups are symmetric (AES-256-GCM under an Argon2id key from a recovery code or passphrase), so a quantum computer does not threaten them. Every key exchange is classical: the phone-to-phone migration link runs SPAKE2 over `Ed25519Group`; the §23 helmet channel, ruled 2026-11-13 and not built, is SPAKE2, then static X25519, then Noise_IK over X25519; the SHDR fleet upload is HPKE DHKEM(X25519). Firmware images and session protocols are signed with Ed25519. Traffic recorded today on an elliptic-curve channel can be decrypted once a large quantum computer exists, and UHDR stays sensitive for a lifetime. Nothing in the repository mentions post-quantum cryptography. **Decision owed (principal, with the `OI-EMMC2-02` cryptography reviewer), brief `docs/human-input/oi-priv-73-post-quantum-key-exchange.md`:** Q1, make the helmet channel hybrid (X25519 with ML-KEM-768, FIPS 203) on every connection before it is built (recommended), at pairing only, or keep the ruled design; Q2, the migration link follows Q1 at low priority (its bundle is sealed before it travels); Q3, the SHDR upload waits for a standardised hybrid HPKE suite; Q4, make the bootloader's verification key replaceable or the image signature hybrid (ML-DSA, FIPS 204) before the first production key is fixed, with `OI-PRIV-32`. Nothing built. Owner: the principal; Firmware + cryptography reviewer.
