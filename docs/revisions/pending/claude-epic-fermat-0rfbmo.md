## NP-NPPS-REF-001
author: NeurOne Software Engineering
text: **§1.6, §14: new `REQ-NPPS-34`, the predefined library loads whole or not at all.** "The whole tree loads before resolution" now says what a runtime does when a file does not load: it reports the load as failed, naming each file, offers nothing from that attempt, and starts again on the next attempt; it never reads the file as one that defines nothing, and it parses nothing before its parser is loaded. Found in the web app on 2026-11-25: in about one load in three `00-zones.npps` and `00-conditions.npps` were parsed before the WebAssembly core had loaded, the parse threw, the loader read the throw as an empty file, and the library was offered with every zone and condition unbound. The web loader (`app/web/src/lib/predefinedProtocols.ts`) now awaits the core, refuses a response that is not a success, fails the whole load on any file and caches nothing from it, and the protocol menu says the library did not load and offers to try again; `main.tsx` imports the app only after the core is loaded. Tested in `app/web/src/lib/predefinedProtocols.test.ts`. No grammar, range or limit changes.
