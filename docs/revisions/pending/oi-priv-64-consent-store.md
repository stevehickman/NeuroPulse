text: - [ ] **`OI-PRIV-64` (raised 2026-11-21, `NP-PRIV-ANALYSIS-007` Findings M5, M6, M8, L10, L11, L15; `CLAUDE.md` §5.1, §6.0, §6.1, §6.2; `REQ-CONSENT-15`, `-20`, `-23`; `common/core/.../consent/ConsentStore.kt`, `common/core/.../models/ConsentModels.kt`) — consent-store defects found after `OI-PRIV-06` closed.** (1) **M5, checked.** `expandClinicianAccess` grants `newTier.uhdrElements - grant.approvedElements`, and `ClinicianAccessExpansionRequest` carries only `toTier`, so widening a grant gives every element of the new tier, not what the use cases need (`REQ-CONSENT-15` (a)); a request for the grant's own tier also counts as a widening. (2) **M6, checked.** `updateResearchConsent` decides a withdrawal from `wasBlanketGranted`, which reads false on the defaults used while the record is unreadable, so a screen commit with L3 off writes no withdrawal day, does not revoke research analytics and does not forget the portal token; `withdrawBlanketResearchConsent` handles the same state with `mayHaveBeenGranted` (`REQ-CONSENT-20` (c)). Whether such a commit is "saying stop" may need a ruling. (3) **M8, checked.** The quarantine keeps an unreadable research record verbatim and for good, contact method included, so turning L1 off does not erase the address everywhere (`REQ-CONSENT-23` (c)); decided and expired invitations and decided expansions have no retention limit. (4) **L10, checked.** `revokeClinicianAccess` deletes the grant, so the person loses the record of who had access, to what and when (§5.1: clinician access is audited). (5) **L11, checked.** `grantClinicianAccess` does not check scopes against the use cases and the tier, silently replaces a grant with the same id, and accepts any expiry. (6) **L15, reported.** A stop caused by a consent withdrawal is recorded as `Declined` on the invitation, where §6.2 makes an opt-out a withdrawal. **Closes when:** each is fixed with a test or ruled acceptable, (1) and (2) first. **Fixed 2026-11-22 (branch `claude/oi-priv-64-consent-store`; `common/core/.../consent/ConsentStore.kt`, `ConsentEngine.kt`, `models/ConsentModels.kt`; tests in `ConsentStoreTests.kt` and `ConsentRepairTests.kt`):** (1) **Fixed.** `ClinicianAccessExpansionRequest` carries `useCaseIds`; `ConsentEngine.accessDifferential` takes the request and adds `minimumNecessaryElements(ids) ∩ toTier.uhdrElements − approved`, which is what `approveExpansion` applies, and the ids join the grant's. A request naming no use case, one the target tier does not offer, or a lower tier has no differential, so an own-tier request widens only by its use cases (`REQ-CONSENT-15` (f); `wideningAddsOnlyWhatTheRequestedUseCasesNeed`, `aRequestForTheGrantsOwnTierWidensOnlyByItsUseCases`, `aRequestedUseCaseAboveTheTargetTierIsRefused`). The use-case tables are unchanged (`NP-PRIV-ANALYSIS-006` F-08, `OI-CONSENT-08`); widening to Full Clinical no longer hands over `EYE_STATE_LOGS`, which no use case needs. (2) **Fixed in part.** A commit with L3 off while the record is unreadable revokes research analytics and forgets the portal token, as `withdrawBlanketResearchConsent` does, and records the blanket withdrawal (day and mark) when it consents to no category (`REQ-CONSENT-20` (c); `aCommitWithBlanketOffWhileTheRecordIsUnreadableIsRecordedAsAWithdrawal`, `aCategoryCommitWhileTheRecordIsUnreadableTearsDownButDoesNotBarItsOwnScope`). A commit that consents to a category records no withdrawal: a recorded one outranks the L2 ticks (`REQ-CONSENT-04` (e)) and would bar the scope the person chose in the same step. (3) **Fixed in part.** Turning L1 off, by a commit or a restored withdrawal, blanks the contact method and channel in every quarantined research record, and in the escaped text of an unreadable quarantine list, keeping every withdrawal mark (`REQ-CONSENT-23` (c); three tests). Not scrubbed: a record so damaged that its `contactMethod` key is illegible, and the tail of a pre-`REQ-CONSENT-23` free-text method containing a quotation mark. (4) **Fixed.** A revoked grant is kept, inactive, with `revokedOnDay`; revoking again keeps the first day; the dashboard shows it as revoked with no revoke button (new key `DASHBOARD_GRANT_REVOKED_FORMAT`, all eleven locales, English text) (new `REQ-CONSENT-25` (a)–(c); `revokingKeepsTheGrantAsAnInactiveRecord`). (5) **Fixed, except the expiry.** `grantClinicianAccess` refuses a grant whose use cases the tier does not offer, whose scopes reach an element those use cases do not need, that carries no scope, or whose id is already held, live or revoked (`ConsentEngine.isWellFormedNewGrant`; `REQ-CONSENT-15` (g), `REQ-CONSENT-25` (d)). No longest expiry is set: it would be a number with no derivation (`CLAUDE.md` §18, §19), so how long stays the person's decision. (6) **Fixed.** A stop a consent withdrawal causes, and an L3 opt-out through `declineInvitation`, are recorded as the new `StudyDecision.Withdrawn`; declining a consent request stays `Declined` (`REQ-CONSENT-11` (c)). **Open:** (a) **ruling, (2):** whether a quarantined commit that turns L3 off and ticks categories is "saying stop"; if it is, the withdrawal mark has to be recorded without barring the categories committed with it, which `REQ-CONSENT-04` (e) does not allow today. (b) **proposal, (3), retention:** a period for closed invitations and decided expansions would be a number with no derivation, so none is set. Proposed instead, needing no number: once an invitation is closed, its descriptor has expired (`notExpired` already refuses it again) and no active participation needs its categories (`ConsentStore.categoriesOf`), reduce it to study id, posture, decision and day, which is all `hasDecided` reads; a decided expansion is kept while its grant is held, as the grant's audit record. Needs the principal's agreement before it is built. (c) The iOS Swift twin (`app/ios/NeurOne/Consent/ConsentStore.swift`, `ConsentEngine.swift`) is not changed: `#947` did not keep it in step either, and `check-consent-reachability` compares only the method surface, which is unchanged. **Not closed:** (2) and (3) are fixed only in part.
