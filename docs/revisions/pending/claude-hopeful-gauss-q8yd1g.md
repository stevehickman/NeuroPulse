The apps let one install hold several `NPIndividualProfile`s (`NPLimitsStore`), and the active profile's tag is sent to the hub, but research consent (L1 to L4), the biometric (BIPA) release, the research-analytics key and the session history are each one per install. **Consequences:** one person's blanket (L3) grant or biometric release is applied to everyone who uses the install; every profile sees every other profile's history; and a withdrawal by one wearer withdraws for all. **Two ways out, a decision (principal, with the App Lead):** (a) key consent, the biometric release and the history by profile, so that choosing a profile chooses its consent and its history, with the migration and backup carrying each profile's state separately; or (b) limit an install to one wearer, drop multiple individual profiles, and say so, which leaves a clinic one install per patient. Either way the warranty owner's consent stays per helmet and separate (`REQ-SHDR-08`). Related: `OI-PRIV-19` (how the same stores behave under the presence gate), `OI-PRIV-20`. **Closes when:** the principal has chosen (a) or (b), the rule is in `NP-SW-001`, and the stores follow it on every host. **Added 2026-11-21 (`NP-PRIV-ANALYSIS-007` Finding M3, checked).** The analytics identity is per install as well: `PostHogAnalyticsBackend` keeps one `distinct_id` and `ResearchAnalyticsGate` one flag, so on a shared install the wearers' analytics events merge under one pseudonym, and rotating the id on one wearer's withdrawal rotates it for all. Option (a) keys the id by profile with the consent, and closes the gate when no profile is active; option (b) makes the point moot. **Decision brief, 2026-11-25:** `docs/human-input/oi-priv-59-one-install-several-wearers.md` (GitHub #1061), DRAFT, not sent; it asks Q1 (several wearers each with their own state, or one wearer per install), Q2 (whether each profile is sealed under its own key) and Q3 (what becomes of the existing state), and recommends Q1 A, Q2 B, Q3 A.

No event is sent by any app yet (`OI-PRIV-05`), so nothing is exposed while this is open. **Closes when:** the principal has chosen, `REQ-CONSENT-14` and `REQ-CONSENT-28` say the same thing, and the switch follows it. **Decision brief, 2026-11-25:** `docs/human-input/oi-priv-77-analytics-and-blanket-consent.md` (GitHub #1062), DRAFT, not sent; it asks Q1 (the three options above) and Q2 (if analytics is its own consent, whether an L3 withdrawal still turns it off), and recommends Q1 A, Q2 A, option A being the easiest to explain to a user.
