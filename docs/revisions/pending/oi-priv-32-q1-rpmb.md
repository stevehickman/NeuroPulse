## CLAUDE.md
text: **Rev {CLAUDE.md to} ({date}) — §23: one recorded exception, recovery USB DFU, which carries a signed firmware image in plaintext on four conditions. No other locked decision changed.**
text: **What changed.** §23 gains one bullet. Recovery USB DFU (`firmware/bootloader/src/np_dfu.c`) is excepted from the encryption rule on four conditions: it stays download only; every image passes the Ed25519 check and the rollback floor (`REQ-SW02-15`) before any bank write; it carries nothing but a signed firmware image; and it is revisited when the `OI-SIMFW-71` secure channel exists or firmware secrecy becomes a requirement. The detail is in `NP-FW-HUB-001` §2.5. No other path is excepted.
text: **Why.** The principal accepted the recommendation of `docs/human-input/oi-priv-32-firmware-rollback-floor-and-dfu.md` §6 (`OI-PRIV-32` (NP-PRIV-ANALYSIS-004), Finding M6). DFU carries no user data, so encryption serves no privacy purpose; the signature and the rollback floor stop injection; image secrecy would cost a key resident on every device and more code in the last-resort recovery path. DFU has never been encrypted, so the exception lowers no protection.
