# ci/host-test-partition.txt — every CMake host-test target, and which half owns it.
#
# NP-SW-CI-001 §6.10, OI-SWCI-14 + OI-SWCI-37. One line per `add_test(NAME …)`
# in the NP_BUILD_TESTS build, as `<class> <ctest name>`:
#
#   C  Class C — run by safety-mcu-ci.yml, selected by `ctest -R "$NP_SAFETY_TESTS"`
#   B  Class B — run by firmware-cross-build.yml, selected by `-E "$NP_SAFETY_TESTS"`
#
# Why a NAME list and not just the counts. The three NP_*_TEST_COUNT variables
# catch a target added or lost; they cannot catch a target renamed, or one
# target swapped for another, or a target moved between halves while a second
# moves the other way — 11 + 38 = 49 holds across every one of those.
#
# What enforces it:
#   scripts/check-ci-scope.ts (correspondence E, every PR touching firmware/,
#     ci/, scripts/ or a workflow) — this list equals the add_test() names the
#     CMake host build registers; every workflow's copy of NP_SAFETY_TESTS is
#     byte-identical; that regex puts every name in the half this file says;
#     and every NP_*_TEST_COUNT copy equals the count of its class here.
#   build-all.yml (weekly) — the same list diffed against `ctest -N` of a real
#     configure, which is the backstop for a test the static parse cannot see
#     (one registered from a foreach() or a function, say).
#
# Adding a host test: add the add_test(), add the line here, and bump the
# count(s) in the workflows. The gate names every place that disagrees.
# Moving a target between halves is a Class C / Class B decision (IEC 62304),
# not a CI edit — the regex, this file and both counts change together.
#
# Sorted by class, then by name. Blank lines and `#` comments are ignored.
